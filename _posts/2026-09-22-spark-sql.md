Bài viết này tiếp nối bài [Apache Spark Overview](/blog/2026/spark-overview/), đi sâu vào Spark SQL: cách đọc dữ liệu từ các định dạng phổ biến (CSV, JSON, Parquet) thành bảng, và các mẫu truy vấn SQL thường dùng khi phân tích dữ liệu trên Spark — từ `SELECT`, `JOIN`, `GROUP BY` cơ bản đến window function và subquery.

## Create table

Giới thiệu 3 định dạng dữ liệu phổ biến và cách đọc mỗi loại thành DataFrame bằng `spark.read`, sau đó đăng ký thành bảng/view để truy vấn bằng SQL qua `spark.sql(...)`.

- Đọc CSV (`header`, `inferSchema`, `sep`)
- Đọc Parquet (schema tự mô tả, columnar, nén tốt — so sánh nhanh với CSV/JSON)


```sql
CREATE TABLE IF NOT EXISTS employees (
  id      INT     COMMENT 'Mã nhân viên, khoá chính',
  name    STRING  COMMENT 'Họ tên đầy đủ',
  city    STRING  COMMENT 'Thành phố nơi làm việc',
  salary  DOUBLE  COMMENT 'Lương theo tháng, đơn vị USD'
)
COMMENT 'Bảng thông tin nhân viên, cập nhật hàng ngày từ hệ thống HR'
STORED AS PARQUET
LOCATION 'path/to/employees';

-- Xem lại comment của bảng và từng cột
DESCRIBE TABLE EXTENDED employees;
```

Với file CSV dùng ký tự phân tách khác dấu phẩy (ví dụ `|`), khai báo thêm `delimiter` (hoặc `sep`) trong `OPTIONS`:

```sql
CREATE TABLE IF NOT EXISTS orders (
  order_id     INT     COMMENT 'Mã đơn hàng, khoá chính',
  customer_id  INT     COMMENT 'Mã khách hàng',
  product      STRING  COMMENT 'Tên sản phẩm',
  amount       DOUBLE  COMMENT 'Giá trị đơn hàng, đơn vị USD'
)
USING csv
COMMENT 'Bảng đơn hàng, dữ liệu nguồn dạng CSV phân tách bằng dấu |'
OPTIONS (
  path "path/to/orders",
  header "true",
  delimiter "|"
);

SELECT * FROM orders LIMIT 10;
```

> **Lưu ý:** khi đặt tên bảng, nên theo format `[source_system]_[table_name]` (ví dụ `hr_employees`, `erp_orders`) thay vì chỉ dùng tên bảng đơn thuần như `employees`, `orders`. Cách đặt tên này giúp:
>
> - Biết ngay dữ liệu bảng đến từ hệ thống nguồn nào chỉ bằng cách nhìn tên bảng, không cần tra lineage/metadata.
> - Tránh đụng tên khi nhiều hệ thống nguồn cùng có bảng trùng tên (ví dụ cả HR và ERP đều có bảng `employees`).
> - Dễ nhóm, filter bảng theo nguồn khi liệt kê danh sách bảng trong catalog.

## SELECT và các phép lọc cơ bản

Cú pháp `SELECT ... FROM ... WHERE ...` trong Spark SQL, chọn cột, đặt alias, lọc điều kiện, `ORDER BY`, `LIMIT`, `DISTINCT`.

```sql
SELECT column1, column2 AS alias_name
FROM my_table
WHERE condition
ORDER BY column1 DESC
LIMIT 10;
```

## JOIN

Các loại join: `INNER JOIN`, `LEFT/RIGHT OUTER JOIN`, `FULL OUTER JOIN`, `CROSS JOIN`, và lưu ý về shuffle khi join hai bảng lớn (liên hệ lại phần wide transformation ở bài overview).

```sql
SELECT a.*, b.*
FROM table_a a
INNER JOIN table_b b
  ON a.id = b.id;
```

## GROUP BY và HAVING

Tổng hợp dữ liệu theo nhóm với `GROUP BY` và các hàm aggregate (`COUNT`, `SUM`, `AVG`, `MAX`, `MIN`), lọc kết quả sau khi group bằng `HAVING` (khác với `WHERE` lọc trước khi group).

```sql
SELECT city, COUNT(*) AS num_people, AVG(age) AS avg_age
FROM my_table
GROUP BY city
HAVING COUNT(*) > 1;
```

## Window Function

Khái niệm window function: tính toán trên một "cửa sổ" các dòng liên quan mà không gộp (collapse) dòng như `GROUP BY`. Cú pháp `OVER (PARTITION BY ... ORDER BY ...)`.

```sql
SELECT
  name,
  city,
  salary,
  AVG(salary) OVER (PARTITION BY city) AS avg_salary_by_city
FROM my_table;
```

## RANK, DENSE_RANK, ROW_NUMBER

So sánh 3 hàm xếp hạng thường bị nhầm lẫn:

- `ROW_NUMBER()`: đánh số thứ tự duy nhất, không có giá trị trùng nhau
- `RANK()`: các dòng bằng nhau nhận cùng hạng, hạng tiếp theo bị nhảy số
- `DENSE_RANK()`: các dòng bằng nhau nhận cùng hạng, hạng tiếp theo không bị nhảy số

Có thể minh họa bằng một bảng ví dụ trước/sau khi áp dụng cả 3 hàm trên cùng một tập dữ liệu có giá trị trùng nhau.

```sql
SELECT
  name,
  city,
  salary,
  ROW_NUMBER() OVER (PARTITION BY city ORDER BY salary DESC) AS row_num,
  RANK()       OVER (PARTITION BY city ORDER BY salary DESC) AS rnk,
  DENSE_RANK() OVER (PARTITION BY city ORDER BY salary DESC) AS dense_rnk
FROM my_table;
```

## Subquery

Subquery trong `WHERE` (scalar/`IN`), subquery trong `FROM` (derived table), và correlated subquery (subquery tham chiếu đến cột của query bên ngoài).

```sql
SELECT name
FROM my_table
WHERE salary > (SELECT AVG(salary) FROM my_table);
```

## WITH (Common Table Expression)

Dùng `WITH` để đặt tên cho một subquery, giúp truy vấn dễ đọc hơn khi cần tái sử dụng cùng một tập kết quả trung gian nhiều lần.

```sql
WITH city_avg AS (
  SELECT city, AVG(salary) AS avg_salary
  FROM my_table
  GROUP BY city
)
SELECT t.name, t.city, t.salary, c.avg_salary
FROM my_table t
JOIN city_avg c ON t.city = c.city
WHERE t.salary > c.avg_salary;
```

## View và Temporary View

Phân biệt `createOrReplaceTempView` (chỉ tồn tại trong session hiện tại) và `createOrReplaceGlobalTempView` (dùng chung giữa nhiều session, lưu trong database `global_temp`). So sánh với view thông thường trong các hệ quản trị cơ sở dữ liệu (database view).

```python
df.createOrReplaceTempView("my_table")
df.createOrReplaceGlobalTempView("my_global_table")

spark.sql("SELECT * FROM my_table")
spark.sql("SELECT * FROM global_temp.my_global_table")
```
